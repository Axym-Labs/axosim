# Bounded Autoresearch: CoreNEURON/Hay Simulator Metrics

Date: 2026-06-05

## Target

Improve defensible model metrics for the NEURO-BENCH single-neuron surrogate
paper after replacing the Arbor path with a CoreNEURON-compatible Hay path.
The current loop is a fast, parallelizable training/data-policy loop on the
accepted fixed teacher dataset; it must not be interpreted as additional
simulator calibration.

## Hard Constraints

- Correctness and simulator defensibility dominate metric improvement.
- Do not use model training runs larger than `80k` presentations for the
  current metric-measurement phase.
- Use Mamba first for model measurements because it is faster.
- Do not count faster convergence tricks as a valid simulator improvement unless
  the change remains defensible for longer runs.
- Do not select validation seeds/splits merely because they improve RMSE.

## Baseline

- Simulator path: CoreNEURON-compatible Hay L5PC with deterministic synapse
  subsets matching the source-teacher deterministic release policy.
- Accepted fixed teacher setting: unchanged source event schedule with
  conductance-side E/I balance E=`0.925`, I=`1.0`, selected for matching the
  historical teacher distribution rather than for lowest model RMSE. This
  supersedes an earlier sampler-side calibration parameterization.
- Dataset baseline:
  `data/hay-coreneuron-source-train32-exc0925-20260605/train` and
  `data/hay-coreneuron-source-val16-exc0925-20260605/val`.
- Model baseline: Mamba `80k` trained on the accepted teacher dataset:
  M1 RMSE/AUC `0.8763 mV / 0.9632`, near-spike RMSE `4.6860 mV`,
  timing F1 matched `0.1468`.
- Primary metric: M1 soma RMSE, guarded by M1 AUC, M2 near-spike RMSE,
  spike-count error, prevalence-matched spike-timing F1, sanity flags, and
  diagnostic trace plots.

## Candidate Interventions

1. **Control:** `baseline_repro` re-runs the accepted Mamba protocol on the
   same train/val data to anchor stochastic comparisons.
2. **Scientific/training-policy:** `longctx1000` doubles context and burn-in.
   Premise: slow NMDA/membrane state may be underconditioned by 500-step
   windows.
3. **Blind but question-aligned:** `soma075` changes the supervised objective
   toward voltage RMSE. It can improve the finite-80k metric, but does not
   establish simulator correctness.
4. **Scientific/diagnostic:** `slope005` adds a voltage-slope loss. Premise:
   derivative fidelity may reduce near-spike and high-dV/dt voltage errors.
5. **Scientific/diagnostic:** `sparse005` adds sparse soma emphasis on rare
   voltage/high-dV/dt/event regimes. Premise: rare regimes dominate RMSE
   tails.
6. **Data-policy:** `official_sampling` uses the deterministic official-style
   file/time sampling policy. Premise: closer sampling to prior Branch-ELM
   practice may reduce data-policy mismatch.

## 2026-06-19 Robustness/OOD/Local-Stability Probe

- Target: find additional defensible benchmark failure modes beyond clipping,
  especially adversarial robustness, OOD/regime behavior, and local stability.
- Hypotheses:
  - OOD/regime evaluation may preserve high AUC while degrading voltage
    fidelity, event timing, or operating-threshold transfer.
  - Sparse gradient-targeted event insertions/deletions may move model outputs
    much more than random edits with the same edit counts.
  - Local affine approximations may fail under adversarial directions; because
    downloaded official checkpoints use `SiLU`, this must not be called a
    literal ReLU linear-region result.
- Baseline/control structure:
  - Teacher-grounded rows use original NeuronIO pickles and fixed validation
    thresholds.
  - Adversarial rows compare gradient-targeted event edits to random edits
    with the same insertion/deletion counts.
  - Local-stability rows compare random Gaussian directions to gradient-sign
    directions.
- Scope rule: adversarial and local-stability rows are model-only unless the
  teacher is re-simulated for perturbed inputs.
- Outputs:
  - `docs/verify-arbor-simulator/artifacts/robustness_ood_stability_20260619/`
  - `docs/verify-arbor-simulator/artifacts/robustness_stability_windowrep_branchbest_20260619/`
  - `docs/verify-arbor-simulator/artifacts/robustness_ood_stability_interpretation_20260619.md`
